## Findings

- **FACT [E1/E2]** Two classical directions: **bottom-up** (statement → chunks → higher abstractions) and **top-down** (domain hypotheses refined via **beacons**/cues). Surveyed in reviews citing Shneiderman/Pennington (bottom-up), Brooks/Soloway (top-down). [Storey et al. program understanding tools paper PDF; AMI review PDF; Peitek ICSE doctoral symposium PDF — accessed 2026-07-27]
- **FACT [E1/E2]** **Integrated metamodel** (von Mayrhauser & Vans): programmers switch among strategies; understanding built concurrently at multiple abstraction levels. [IEEE survey DOI 10.1109/2.402076 abstract/metadata; Storey PDF summarizing von Mayrhauser & Vans]
- **FACT [E2]** Top-down preferred when familiar; novices often fall back to bottom-up (higher cognitive effort). [Peitek]
- **INFERENCE [E4]** Agent research protocol should support **opportunistic switching**: structure/map first (top-down hypotheses), then targeted reads (bottom-up), with explicit hypothesis validation — not only linear file dumps. Premises: integrated metamodel + beacon/hypothesis literature above.
